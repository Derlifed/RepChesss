# RepChess

Chess opening trainer. A static site (`index.html`) plus a few Vercel Functions in `api/` for accounts and progress sync.

## Deploy on Vercel

1. Import the repo at vercel.com/new. Leave the framework as **Other** and the build command empty.
2. **Storage → Create Database → Neon (Postgres)** and connect it to the project. This sets `DATABASE_URL`. The tables are created automatically on the first request.
3. Add environment variables (Settings → Environment Variables):

   | Name | Required | What it is |
   | --- | --- | --- |
   | `AUTH_SECRET` | yes | Long random string that signs login cookies. Generate one with `openssl rand -base64 32`. |
   | `RESEND_API_KEY` | for "Forgot password" | API key from resend.com. Without it, the reset form says reset email is not set up. |
   | `EMAIL_FROM` | with Resend | Sender, e.g. `RepChess <noreply@yourdomain.com>`. Verify that domain in Resend first. |
   | `SITE_URL` | no | e.g. `https://yourdomain.com`. Used in the sitemap, robots.txt and reset links. Defaults to the project's production domain. |

4. Redeploy, then add your domain under Settings → Domains.

If you skip Resend, delete the Resend line from `privacy.html`.

## Local development

```
npm install
npx vercel link
npx vercel env pull
npx vercel dev
```

## How it works

- **Accounts:** email + username + password (8+ characters). Passwords are hashed with scrypt. A signed, HttpOnly cookie (`rc_session`) keeps you logged in for 30 days. There is no email confirmation step.
- **Rate limits:** login, sign up and password reset attempts are throttled in the database.
- **Sitemap:** `/sitemap.xml` and `/robots.txt` are generated by `api/sitemap.js` and `api/robots.js` (wired up in `vercel.json`). Add new pages to the `PAGES` list in `api/sitemap.js`.
- **Deleting a user:** `DELETE FROM users WHERE email = '...'` removes their username and progress too.
